An end-user and adversarial pass over Lagrange 1.2.1 (`night/base`: v1.2.1 plus the empty
built-in sensor-kinds registry), on the shared overnight machine (RTX 4060 Laptop, about nine
agents building and running at the same time, so timings are pessimistic). Everything ran headless
(`--no-ros` unless ROS was the point, `ROS_DOMAIN_ID=69`).

Fixed items have a regression test and a commit on `night/qa`; open items say where the fault is.

## Details

### 1, 2. A step that never ends (fixed)

Repro (protocol): connect, send `ClientHello{version 0.1}`, then
`Command{step{ticks: 4000000000}}`. The server steps 46 simulated days inside one call of
`Impl::command` (`server/src/Server.cpp`, `case v1::Command::kStep`) before reading any socket;
other clients get nothing, and SIGTERM sets `gStop`, which is checked only between `runOnce`
calls (`server/src/CommandLine.cpp`), so only SIGKILL stops it.

Repro (ROS): `set_simulation_state` paused, then `step_simulation{steps: 9223372036854775807}`:
the call times out and so does every later service (`Impl::stepTicks`).

Expected: refused, or run without blocking. Fix: a Step is at most 600 s of simulation time
(`kMaxStepCommandNs`) and `step_simulation` at most 10⁶ ticks (`kMaxStepTicks`); larger ones are
refused with a message pointing to Play. Test `ServerTest.RefusesAStepTooLongToRunAtOnce`. Not
covered by a test: the ROS path (same constant, three lines). Still open: SIGTERM is not seen
during a long (now bounded) step; stepping in slices from the main loop would fix both.

### 25, 26. Profiles in `lagrange run`, `validate`, `determinism` (fixed)

Lead from the viewer-perf agent. Repro: `lagrange run profiles/examples/quad_x500_downwash.yaml
--robot assets/robots/quad_x500/quad_x500.usda --world none --no-ros` printed `[rotor_aero] the
rotors do not run without the site's air density` though the profile has
`rotor_aero.air_density: 1.225`; the quadcopter then hovered at 2 m, so only the note was wrong.
`serve()` (and Python, `validate`, `graph`) call `Server::load()`, which builds the run without
the profile, then `applyProfile`, which builds it again: the first build's notes are about a run
that never steps. Fix: `ServerOptions::profileFollows`; such a load keeps its modules' notes
(errors still pass), the run built with the profile says what still holds. Test
`Profile.ALoadAProfileFollowsKeepsNotesTheProfileAnswers`.

Looking at the same code: `lagrange determinism PROFILE` (`server/src/cli.cpp`) read the profile
for its stage and plugins only and stepped the server's defaults. Each run now applies it. With
that, every example profile that runs here was checked for 5 s: `quad_x500_bem`, `_downwash`,
`_live_air`, `_power_line`, `_gusty`, `amr_fog`, `led_heatsink`, `sedan_city`: all identical.

### 3. Restoring a run with a camera (fixed)

Repro: `s = lagrange.Simulation(lagrange.sample_sedan(), world=None); s.step_until(5);
st = s.save_state(); s.step_until(5.5); h = s.state_hash(); s.restore_state(st);
s.step_until(5.5); s.state_hash() == h` → False (also into a fresh `Simulation`). Every signal
read the same; the difference was the image handles: `SignalBus::published_` (the per-slot publish
counter) is not part of the state, so a restored run numbered its images differently, and a
restored handle never resolved. Fix in `Scheduler::restoreState`: the counters continue from the
restored handles, and kept buffers (possibly from another timeline) are dropped. Test
`State.RestoredRunPublishesTheSameBufferHandles`; checked end to end with the sedan, arm6 and
town samples. `lagrange determinism` (two fresh runs) was never affected.

### 4. Command-line numbers (fixed)

Taken before the fix (`lagrange_server --no-ros --world none ...`): `--ambient-temperature inf`
and `--tether 0,0,0,base_link,inf` (both: "MuJoCo found a non-finite acceleration" at t = 0),
`--geo-origin nan,8,400` (`std::abs(nan) > 90` is false), `--air-density inf`, `--rtf inf`,
`--humans nan|inf|1e12` (cast to int: undefined), `--traffic vehicles=99999999999`,
`--joint-loop-hz nan|inf|5abc` (`atof`), `--emi-motor-leads 0.1junk|inf`,
`--weather temperature=nan,...`, `--spawn 1,2,3,4,5` (fifth value dropped). Test
`CommandLine.RefusesNumbersThatAreNotFiniteOrDoNotFit`.

### 6. `lagrange tunnel` (fixed)

`lagrange_tunnel quad_x500.urdf --yaw nan --cpu` → exit 139. `--frames -1` → `size_t(-1.0)`, ran
past 120 s. `--cells 0|-3|1` → a grid of zero or one cell, results written anyway. Fix: the command
line reads each number whole; `runWindTunnel` refuses non-finite speed, yaw, clearance, passes
and fewer than `kMinTunnelCells` (1000). Test `WindTunnel.RefusesOptionsItCannotRun`.

### 7. Memory before the handshake (open)

Repro: 8 Unix-socket clients each send the header `60 MiB` and 59 MiB of zeros, no ClientHello:
server RSS 85 MB → 626 MB. 3000 idle connections are all accepted (the process limit is 524288
files) and cost about half a core in polling. The same holds on `tcp://` with
`--auth-token-file`, since the token is checked only in ClientHello. Suggested fix: a small frame
limit (say 64 KiB) until the session is greeted, and a cap on sessions; the limit lives in
`proto::FrameReader` (`proto/framing`), so it needs the protocol owners' review (RFC 0007 rules
for `proto/`).

### 8. Names the bus refuses (fixed, with an open design question)

`checkSignalName` (`core/signals/src/SignalBus.cpp`) printed `name[i]` as one byte. It now names
the whole UTF-8 character. Open: any URDF joint or link name with a space or a non-ASCII letter
stops the run ("character ' ' not allowed"); the importers could map such names to signal-safe
ones instead.

### 12 to 24 (open)

- 12: `bridges/ros2/src/Bridge.cpp`, `set_simulation_state`: `target > Quitting` covers 4 and 5

- 13: `server/src/Server.cpp`, `default:` of `Impl::command`.
- 14: `python/src/bindings.cpp`, `Simulation::read`: say the signal is an image/handle.
- 15: `server::loadModel` (`server/src/Robot.cpp`) reports the parser's failure for a missing

- 16: `server/src/Robot.cpp` around the `kPlaceholderMassKg` note.
- 17: `Impl::storeSite` (`server/src/Server.cpp`) checks every name but `gravity` and `wind_from`.
- 18: `Server::restoreState`: no check that the reader is at its end.
- 19: `tools/migrate` recording check reads the summary section the crash never wrote.
- 21: `profiles/examples/*.yaml` `stage:` lines from the CLAUDE.md §11 sketches.
- 23: `assets/worlds/amr_fms_warehouse/warehouse.sdf` with the swerve AMR; ServerStats showed

## Checked and found sound

- Samples `amr people empty sedan town quad lexus x500 swerve`, 40 s each with
  `lagrange NAME --server-only --no-ros`: RSS flat (60 to 355 MB), no errors; all but swerve at
  real time (ServerStats).
- Python over 20 s of amr, sedan, quad: no NaN in any numeric signal (lidar `inf` is the no-return
  convention, radar padding NaN).
- `lagrange determinism`: default AMR, sedan in the town, `--humans 6`, the swerve warehouse,
  `--tether`, `--physics jolt`, and (after fix 25) eight example profiles: all identical.
- Save/restore in the same run: amr, quad, tiled town, swerve, led heatsink (and, after fix 3,
  sedan, arm6, town).
- Spawn and delete 60 times into the warehouse: RSS 83 to 84 MB, hashes fine.
- Spawning at 1e5 to 1e300 m: the floating origin keeps the local pose finite.
- Malformed URDFs (empty, truncated, no links, cycles, unknown parent, duplicate names, zero or
  NaN mass, revolute without limits, missing meshes, 1e30 mass): each refused with the parser's
  or MuJoCo's reason or run with a placeholder; none crashed.
- `lagrange_import` URDF, SDFormat and MJCF of the sample AMR → USD → run: same pose after 3 s.
- Profiles: all shipped examples validate (those with a stage that exists); broken YAML, empty
  file, list, unknown domain, NaN geo origin, bad dt, negative RTF, `schema_version: 99`: refused
  with a reason.
- Run files: wrong kinds of values are refused by name (`lagrange RUN.yaml`).
- Protocol: 300 connections of random frames and 400 of bit-flipped valid commands, an
  oversize header, odd subscriptions, NaN RTF, bad prims, `/dev/zero` and directories as
  stages, `/etc/hostname` as a recording: the server stayed up and answered each command.
- ROS `simulation_interfaces`: stepping while playing, empty and unknown entity names, read-only
  `set_entity_state`, `reset_simulation` scope 99: clear results.
- Recording: `--record` to `/proc` or a directory refused; a recording cut by SIGKILL replays.
- Joint commands of 1e9 rad, 1e12 and -1e300 N·m on arm6: clamped, no NaN.

Not done: the libFuzzer harnesses (`proto/framing/fuzz`, `viewer/client/fuzz`) and ASan/UBSan
builds (too heavy for the shared machine tonight); the viewer.
