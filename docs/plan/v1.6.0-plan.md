# v1.6.0 development plan (draft, 2026-11-22)

Written after the v1.5.0 release (2026-11-22, #477). 1.x stays frozen by RFC 0007: schemas, plugin ABI, protocol,
profiles and recordings change only by addition. Items that need an RFC say so. The order is a
proposal; the owner picks.

## Track A: reinforcement learning at scale (proposed headline)

What exists (v1.4.0, #392/#397):
- **Environments:** `lagrange.envs.LagrangeEnv` (Gymnasium interface) runs one simulation per
  process.
- **Parallel workers:** `ParallelEnvs` and `VectorEnv` run them over shared memory, at about
  90 % of independent processes on 12 workers. `send`/`recv` let workers step at their own pace.
- **Randomisation:** `randomize=` for site parameters.
- **Example:** `lagrange_example_rl` (an arm).

What is missing, by size:

| # | Item | Size | Needs |
|---|---|---|---|
| A1 | **Wider domain randomisation**: body mass and inertia, friction, motor and battery parameters, rotor coefficients, sensor noise and latency, start poses, drawn per reset from a seeded stream and recorded in `info` | Small | Server hooks to change these without a rebuild (as `set_site` does), or a rebuild per reset with the same cost as today's `reset` |
| A2 | **Task library and a real training example**: a hover and waypoint task for the quadcopter, a go-to-goal task for the AMR, rewards and terminations documented; a PPO run with Stable-Baselines3 (TODO(verify) its version and licence, MIT) to a stated reward, its curve in the docs | Small–medium | — |
| A3 | **Many environments in one process**: several `Server`s in one process sharing the read-only world tables, so the per-process cost (memory, start-up) does not cap the count | Medium | Thread safety of the module registry and plugins; determinism per environment |
| A4 | **Batched GPU physics**: thousands of environments on one GPU (Tier 2), for example through MuJoCo Warp or MJX (TODO(verify) maturity, licence and the MuJoCo version they need) with Lagrange's other domains in reduced form | Very large | **RFC**: which domains run batched, what a batched step means for the multirate scheduler (invariant 4), the CPU reference (invariant 7), and the profile's `batch` key that does nothing today |
| A5 | **Throughput benchmark**: steps per second for 1, 4, 16 and 64 environments on CPU, with and without sensors, in `docs/design/benchmarks.md` and the nightly benchmarks | Small | — |

Proposed order: A5 (the baseline), A1, A2, then A3; A4's RFC drafted in parallel and built only
after it is accepted.

## Track B: owed physics and realism

- **Joint springs.** RFC 0023 (Draft, #448): `stiffness` and `springReference` on
  `JointDynamicsAPI_1`, carried into both engines and appended to the ABI. It waits on the
  owner.
- **Fluid power.** RFC 0024 (Draft, #461): hydraulic and pneumatic cylinders, valves and pumps.
  It has 15 TODO(verify) and 8 steps, and waits on the owner.
- **Trees, follow-ups from #472–#476:**
  - draw branch wood in the viewer;
  - let cut wood fall as bodies;
  - let branches bend;
  - add crowns to fisheye and thermal cameras;
  - put branches and flying leaves in camera depth;
  - stop leaves on hulls, cylinders and robots;
  - measure thrust of tip-cut propellers;
  - measure leaf areal mass;
  - measure first-mode frequencies of fruit trees.
- **Thin boxes.** A 5 cm landing-pad collider traps the quadcopter (#476). Reproduce it, and fix
  it in the contact setup or document the limit.
- **Validation of water downwash** with OpenFOAM `interFoam`: dimple depth and outwash against a
  VOF case.
- **Blade damage on more than one blade**, and the inertia change of a damaged propeller.

## Track C: usability

- **Report videos** as a tool: `tools/videos/make_videos.py` takes `vid.sh`'s side-by-side
  viewport and scope layout, so every feature can ship a clip.
- **Video timing.** The headless viewer records at 8 fps while writing 30 fps. Add a fixed-step
  record mode, so videos play in real time without `--rtf`.
- **Docs.** Make the tree and orchard pages and the actuator pages tutorials with
  `tools/ci/tutorial_*.sh` checks.

## Release checks

- All packages built and tested (`colcon test` across the tree).
- Determinism CLI tests, the realism run (`tools/ci/realism.sh --offline`), and the debs with the
  install test.
