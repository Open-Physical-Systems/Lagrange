# Lagrange v0.2.0: simulation core and AMR (release notes, draft)

v0.1 was the viewer, the protocol and a replay server. v0.2 is the simulator behind them: a
multirate co-simulation core, MuJoCo physics, lidar and IMU sensors on the CPU and the GPU, a
ROS 2 bridge with ros2_control, and a Nav2 demo, with the v0.1 viewer connecting unchanged.

**Status:** prepared, not published. Merging `dev` into `main` and tagging stay with the owner.

## Highlights

- **Core.**
  - Units checked at wiring, with no silent conversions.
  - A signal bus and a multirate scheduler with holds and feedback inputs.
  - Substitutes for every domain; save, restore and state hashes.
  - Counter-based noise; a floating origin (a world 500 km out simulates like one at the origin).
  - Core services: `wrench_sum`, a run log, `SceneQuery`, bounded consumer rings.
  - A versioned C ABI for third-party modules (ABI 0.1, unstable until v1.0).
- **Physics.**
  - MuJoCo 3.12, validated against closed-form mechanics.
  - The fixed-robot substitute.
  - A Jolt Physics spike, with its gaps listed for the full backend in v0.3.
- **Sensors.**
  - IMU with white noise, bias, random walk, saturation and quantisation.
  - 2D and 3D lidar on Tier 0: exact casts in double, Embree-culled, bit-identical to testing
    every shape.
  - 2D and 3D lidar on Tier 1: a Slang compute kernel over a bounding-volume hierarchy.
  - Wheel encoders through ros2_control.
- **Server and tools.**
  - `lagrange_server` speaks the v0.1 protocol to the viewer.
  - Simulation profiles are validated and applied.
  - MCAP recording.
  - The `lagrange` command: `run`, `validate`, `graph`, `determinism`, `info`.
  - Python bindings (`import lagrange`).
- **ROS 2.**
  - `/clock`, `/tf`, `/odom`, `/joint_states`, `/scan`, `/points`, `/imu`, `/cmd_vel`.
  - The `simulation_interfaces` services.
  - ros2_control in lockstep (`lagrange_ros2_control/LagrangeSystem`).
  - The Nav2 warehouse demo.
- **Formats.** URDF and xacro, SDFormat, MJCF and USD robots and worlds, with a vendored OpenUSD
  26.08 and the first schemas (sensors); glTF, OBJ, STL and Collada meshes.
- **Docs.** A user guide and an AMR tutorial that runs end to end (`tools/ci/tutorial_amr.sh`).
  Benchmarks with recorded baselines.
- **Packaging.** `.deb` packages built with bloom (dry run), and a container image that runs the
  Nav2 demo headless.

## Moved to v0.3, with reasons (`docs/plan/progress.md`)

- G2 overlay files: they need the electrical schemas.
- B8 collision bake: it needs mesh colliders and CoACD.
- E6 scene editing: its test edits a motor parameter.
- E8 replay in the C++ server: comes with the replay substitute.
- H7 thin electrical slice: v0.3 builds the full electrical domain.
- C5 runtime rebase: deferred to v0.7 by the owner.

## Known issues

- **Nav2 start-up:** about half the launches on the development machine have one ROS process
  never discover another's endpoint. Once up, every patrol reached its waypoints without a
  collision. Mitigated by retries and one relaunch in `nav2_demo.sh`; root cause not found
  (`docs/plan/progress.md`).
- **Not run while GitHub Actions are disabled:**
  - the ASan/UBSan build of the USD packages (stopped by the system for low memory);
  - the nightly jobs (benchmarks, determinism, tutorial, Nav2).

  Everything else was verified locally.
